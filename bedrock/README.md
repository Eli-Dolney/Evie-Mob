# LTW Mobs Bedrock 0.2.0

Family test port of Evie the Dragon and Eli, King of the Seas. Designed for
Minecraft Bedrock 1.21.90+, stable @minecraft/server 2.0.0, no experiments.
See PC-Guide.txt for installation, controls, commands, and the acceptance test.
Minecraft import and actual gameplay remain unverified on the development Mac.

## Included

- Updated 98-piece Evie and 88-piece Eli models, original painted textures and
  glow layers, translated Java animations, Creative eggs, and summon support.
- Five-item taming with saved player-specific trust; owner-only saddling,
  follow/stay, and single-rider flight/swimming with dismount protection.
- Rare floating cherry islands over Overworld land, and tropical lagoons in
  warm/lukewarm oceans, generated through native features in new terrain.
- One wild companion per habitat, tracked through persistent marker records.
- Craftable Sky Island and Sea Lagoon Locators using the original Java icons.
  Each guides you to the closest KNOWN habitat in your current dimension.
- 1.6x Sprint boosting, plus a five-second boost by using the matching locator
  while mounted (ten-second cooldown measured from activation).
- Default tamed damage immunity. Optional normal-damage/recovery mode, healing
  with the creature's food, and a saved 30-second recovery rest after a fatal hit.

There are no attacks, breeding, extra dimensions, or vanilla entity overrides.

## Build and source

Install Node.js 20.11+ and Python 3. From this directory:

```sh
npm ci --ignore-scripts
npm run compile
npm test
python3 tools/build.py
```

The .mcaddon and editable source ZIP appear in dist/. Compiled scripts, original
models, and textures are included. Packaging unchanged source needs only Python:
`python3 tools/build.py`. An optional original Java ZIP can be supplied as the
first argument. The original Java mod and its ZIP are never edited.

Edit TypeScript in src/, then compile before building. Geometry, animations,
entity JSON, features, items, recipes, and NBT templates are generated by tools/;
edit those generators or the included models to preserve edits during rebuilds.
`companion-settings.json` controls movement speeds, boosts, and default immunity.
`generation-settings.json` controls per-eligible-chunk candidate probabilities:
1/512 for sky islands and 1/256 for lagoons. These are placement attempts, not
guaranteed spawns. Island placement needs clear air; lagoon placement intersects
only listed natural ocean blocks. After changing either file, rebuild and import
both updated packs. settings.ts/settings.js are generated from the JSON.

behavior_pack/ contains gameplay, block/item definitions, recipes, features,
structures, and compiled scripts. resource_pack/ contains geometry, textures,
animations, localization, and rendering. tests/ includes pure rules and a small
script-host stub for persistence/locator tests; it does not simulate Minecraft.

## Persistence and compatibility

Preserve all pack/module UUIDs when releasing updates. Version 0.2.0 uses the
same fixed UUIDs as 0.1.0 and migrates v1 companion saves to v2 without losing
trust, ownership, saddles, or commands. Saved health/recovery fields are added.
Dynamic properties are scoped to the behavior pack UUID.

Native tameable ownership is reconciled after interrupted saves. Player mount
records protect dismounts after script reloads. Native ride interactions are
canceled before scheduling validated owner-only mutations. Entity properties
synchronize saddle, flight, stay, and recovery appearance to clients.

Each habitat has one ticking crystal marker. The world keeps an individual
versioned dynamic-property record per marker location, including its original
spawn flag and entity ID. The creature stores the habitat ID and home position.
Moving/taming a creature never resets that flag; killing a wild creature does
not respawn it. Interrupted spawn intent is reconciled against nearby entities.
Do not copy or move habitat crystals to create more spawns. Removing a crystal
with Creative/commands prevents future registration but does not erase history.
Habitat registration occurs once its marker loads inside simulation distance.

Locators share discovered habitats across players and retain that history after
reload. They show direction, distance, and coordinates; they do not search
unexplored terrain or register with the vanilla /locate command. If nothing is
known, exploration is required. They point to habitats, not moving companions.

Eli uses bounded look-directed impulses, checking intermediate collision-sized
water footprints, ceilings, shores, and unloaded boundaries. Following uses a
direct reachable water route and waits when blocked or when the owner is on land.
Evie uses native air/ground controls. Empty input hovers; looking down onto open
ground lands. Disconnects and reloads clear unoccupied riding/boost momentum.

## Optional recovery mode

The operator command `/scriptevent ltw_mobs:protection recovery` changes the whole
world to recovery mode; `... immune` restores the default. The choice persists.
Use the same food to heal 12 health per item, capped at 100. Ordinary lethal
hits start a 600-loaded-tick rest with rider ejection and appropriate protection.
Rest pauses while the entity is unloaded/the world closed, then resumes. It
blocks commands, mounting, and damage; the companion stays put and heals at the
end. `/scriptevent ltw_mobs:recover test` tests rest on your mounted or closest
owned companion within 12 blocks, even when immunity is enabled.

Stable API 2.0.0 has no cancellable before-hurt event. Recovery mode therefore
uses a large native health reserve and a saved 100-point gameplay health value;
action-bar text shows gameplay health. Reserve health is refilled after ordinary
hits. Explicit kill commands or damage greater than the reserve can bypass this
mechanism. Native mount hearts may not match the gameplay value; check the
on-screen health text. This mode needs particular in-game verification. Tamed
void detection attempts a return to the saved home if that destination is loaded
and clear. Normal dismount grants slow falling after flight and 60 seconds of
water breathing after underwater riding; Eli also grants underwater night vision.

## Verification

22 automated tests pass: taming counts, consumption, ownership, migration,
health/recovery timing, healing, boost bounds, locator selection, one-time
habitat spawning, interrupted intent, and reload persistence in a script stub.
Scripts type-check against exactly @minecraft/server 2.0.0. Deterministic checks
cover manifests, UUIDs/dependencies, scripts, JSON, two little-endian NBT files,
palette indices, spawn clearance, generation references, item recipes/icons,
186 cubes, every face UV, unchanged creature textures, and animation/event bones.
Habitat block names/states are checked against a bundled relevant subset of
Mojang's official v1.21.90.3 metadata, with source URL retained.

During development, published Mojang entity/block/item schemas also passed
focused checks. Two upstream schema inconsistencies were corrected only in the
validation harness: obsolete expression.schema.json points to the published
molang_expression.schema.json; block loot permits its officially documented
string representation. Item schema checks alone do not prove use-event behavior.

The original Java visual scales (0.55 Evie, 0.74 Eli) remain. Painted face UVs
are preserved rather than trusting the source's misleading box-UV flag. Six Evie
seat faces originally outside the 512-pixel atlas use existing leather pixels at
y=452..456. Original textures are otherwise unchanged. Conversion details are in
conversion-report.json. A previous Blockbench UI attempt did not yield a preview.

Still pending: Minecraft import, generation frequency/placement, crystal ticks,
locator use, visuals, saddle/rider alignment, flight/landing, boosted swimming,
lethal-hit recovery, native hearts, touch/controller controls, and multiplayer.
Start with a new Windows Creative world, then test PC+iPad and PS5 through a Realm.
